1. Current State & Changes Important

The previous walkthrough was stale. The code has since adopted Effect on the backend, split the UI server into focused modules, extracted shared DataScript queries, added localized view error boundaries, and localized debounced text rollback.
  • Backend Effect port: effect and @effect/platform-bun are dependencies. Core I/O, services, action handlers, registry invocation, HTTP routing, and UI session sends now use Effect programs or Layers.
  • UI backend split: surface/ui.ts is now a stable facade. Implementation lives under surface/ui/: server lifecycle, HTTP routing, session hub, assets, build, dev orchestration, saved queries, and paths.
  • Query extraction: standard field/tag/backlink queries live in foundation/query/queries.ts; surface/map.ts imports them.
  • Frontend containment: ViewErrorBoundary wraps lazy Graph and Canvas views while shell chrome remains outside the boundary.
  • Rollback localization: debounced text edits retain a per-node pre-edit payload and reapply pending edits after a resync.

2. Model & Design

kb is a repo-native outliner datastore. Everything is a node: user nodes, fields, tags, commands, saved-query virtual nodes, and canvas/graph configuration. JSONL is the persisted source; DataScript is rebuilt in memory for queries.

Core invariant: fields and tags are graph nodes. Node properties are keyed by field-node IDs, while references point to other node IDs.

  updatedAt: string;

3. End-to-End Flow

CLI / MCP / Browser UI │ ▼ Action Registry ── schema seam ── Effect-native handler │ │ │ ▼ │ KbCtx / KbStore / FileSystem Layers │ │ └──────────────────────────┼──────────────┐ ▼ ▼ JSONL Store DataScript QueryDb │ │ └──────┬───────┘ ▼ ActionReceipt / WS tx / UI state

For a browser mutation, the UI applies a planned local transaction, posts one or more action invocations to /api/action, and receives WebSocket or HTTP authority. On failure, the mutation layer refetches or performs a bounded local recovery.

8. UI Backend Modules

The UI backend has explicit module boundaries:

  • ui/server.ts — Bun.serve lifecycle, WebSocket upgrade callbacks, filesystem watch lifecycle, production/dev orchestration.
  • ui/http.ts — Effect REST/API routing, JSON/plain responses, action invocation, assets/static fallback.
  • ui/session.ts — Effect-valued SubscriptionHub, clients, tx broadcasts, query subscriptions, virtual saved-query nodes.
  • ui/assets.ts — static UI and opaque .kb/assets serving.
  • ui/build.ts — stale/missing UI build detection and production build markers.
  • ui/dev.ts — Vite child process and exit handling.
  • ui/saved-queries.ts and ui/paths.ts — saved-query materialization and path constants.

12. Optimistic Mutations

actions/plan.ts creates pure mutation plans. actions/mutations.ts is the UI command facade. actions/optimistic.ts applies the local transaction, posts actions, and recovers from failure.

Current rollback design: structural or partial-plan failure prefers an authoritative graph refetch. If that fails, recovery removes minted nodes, restores only touched pre-plan nodes, reapplies confirmed non-structural actions, preserves unrelated concurrent nodes, and never rewinds the revision.

Debounced text editing is narrower: it captures the edited node's pre-edit wire payload, refetches without flipping to fixture mode, then reapplies pending local edits. If refetch fails, it restores only that node.
