## Shape

`OutlineState` is still one interface. The data half is derived, not restated:

```ts
export type OutlineStateData = {
  [K in keyof OutlineState as OutlineState[K] extends (...args: never) => unknown
    ? never
    : K]: OutlineState[K];
};
```

`export const initialOutlineState: OutlineStateData` holds the empty values.
The store factory spreads it. Zero behaviour change: `hydrateFromWire` still
writes its own subset and still does not reset `framePages` / `focusSeq` /
`focusX`.

`resetOutlineStore(overrides?)` is
`useOutlineStore.setState({ ...structuredClone(initialOutlineState), ...overrides })`.
`structuredClone` is the one extra step the brief's spread does not say:
spreading the exported const would share the same `Map` / `Set` / array
identities across suites. The clone is derived from the named value, not a
second field list.

Every migrated literal was a subset of the store's own defaults (some listed
10 fields, some 12, some 16; `graph-view.ordering.test.ts` wrote
`"__kb_root__"` instead of `WORKSPACE_ROOT_ID`). No suite passed a field that
differed from `initialOutlineState`, so every call is `resetOutlineStore()`
with no overrides. No test's outcome depended on a stale omitted default —
after counts match before counts.

Two `useOutlineStore.setState` sites remain; they are not resets:

- `node-command-palette.test.tsx` — `{ selectedNodeId }` after hydrate
- `instance-identity.component.test.tsx` — updater that uncollapses `n.root-a`

`rg 'rootNodeId: "__kb_root__"' packages/app/ui/src` hits nothing. The store
and fixture go through `WORKSPACE_ROOT_ID` / `structuredClone`, so the string
is not restated.

## Fixture location

`tools/kb/packages/app/ui/src/test-support/outline-store.ts`.

ARCHITECTURE.md File layout lists production folders (`stores/`, `lib/`,
`api/`, `actions/`) and colocates tests next to units. It does not name a
helper neighbourhood. The two existing candidates are the wrong concepts:

- `src/test-setup.ts` is the Vitest `setupFiles` polyfill (WebGL). Putting the
  fixture there would either auto-reset every suite (behaviour change for
  files that do not reset today) or mix a runner hook with a helper module.
- `src/fixtures/` is graph/seed *data*, not store mechanics.

The gap's `expected` already names "@kb/ui's test support". A new
`src/test-support/` folder is that concept, leaves the production layout
(which u3 does not own) unchanged, and is what ARCHITECTURE.md would predict
once you separate "runner setup" from "test helper".
