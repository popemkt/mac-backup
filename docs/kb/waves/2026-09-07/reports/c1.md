# c1 — `#check` bundled extension

## Outcome

Implemented `@kb/ext-check` as the single owner of rule/check consistency. The bundled extension exposes the read-only `ext.check.audit` action and transactional `ext.check.sync` action, and `check:audit` now closes the workspace `verify` chain. Existing rules point to ordinary `#check` nodes, their enforcement is derived from each check's surface, obsolete gates were removed, the generated rules index was refreshed, and gap `01M1PJXPBSJ6J25ZCEAX0G0AN7` is `done`.

## Audit contract and red cases

The audit emits six finding kinds in deterministic order, with one focused red fixture for each:

1. `check-missing` — a rule's `check` ref targets a node not tagged `check`.
2. `evidence-missing` — a check names a repo-relative evidence file that does not exist.
3. `invocation-unwired` — the declared invocation marker is absent from every file for the check's surface.
4. `enforcement-stale` — stored rule enforcement differs from the enforcement derived from its check surface.
5. `gate-and-check` — a rule retains both the legacy gate and a check ref.
6. `home-broken` — a rule home points to a missing path or to a Markdown anchor with no matching GitHub-slugged heading.

Two additional tests prove that sync followed by audit is clean and that audit is pure by comparing canonical JSONL before and after the read action. Filesystem behavior is supplied through Effect's `FileSystem` service. `SURFACE_FILES` is the only surface-to-file mechanism; exact entries are read directly and its single workflow wildcard is expanded from the containing directory because Node globbing ignores dot-directories even when an explicit `.github` or `.githooks` path is supplied.

## Data model and enforcement

The five existing `enforcement-level` value nodes for `harness`, `lint`, `tsc`, `hook`, and `ci` also carry `check-surface`. One set of nodes therefore serves both concepts, while `prose` remains only an enforcement level because it is the absence of a machine check. This bridge avoids a mirrored value set that would need manual synchronization.

Ten rules remain without a check:

- `Coverage is a signal` and `Mutation score is advisory` deliberately describe advisory evidence rather than blocking enforcement.
- `Effect v4 idiom` keeps its legacy gate because this wave did not mint a `tsc` check for the named `@effect/tsgo` diagnostic path; per the brief, a gate whose check is not represented stays gate-only.

## Wiring and ownership

The runtime and CLI manifests now declare their `@kb/ext-check` workspace dependency, and `tools/kb/bun.lock` follows those manifests. The existing CLI bundled-extension inventory assertion also needed `check` added beside `canvas` and `docs`; this was the smallest ownership expansion required to keep the inventory test truthful.

The CLI prints rule findings as `kind — message (rule <id>)`; the two check-only variants use the corresponding `(check <id>)` subject. The audit currently returns `clean: true` with no findings.
