## Gap 1 — `onOpen` does not cover zoom; `onZoomTo` is required

The remaining store read was `useOutlineStore((s) => s.zoomTo)` inside
`ResolvedRefRow` (was `field-value.tsx:526`). `onOpen` on that row opens the
ref picker. The bullet click and tag-chip click navigate. Those are two
gestures, so they stayed two callbacks.

`onZoomTo(id)` is required on `FieldEditorProps`, the same way `MdView`'s
`onRefClick` is required. Callers that may import stores pass it:

- `fields-section.tsx` — `FieldsSection` reads `zoomTo` and hands it to
  `FieldValueStack`; the stack stays a pure view (`fields-section.test.tsx`
  still renders without a store).
- `board-cards-view.tsx` / `table-view.tsx` — already had `zoomTo` in the
  card/cell; they pass it to `PropValueEditor`.

`field-row.tsx` does not construct `PropValueEditor`. It is the label shell.
The brief listed it as a caller; the actual constructors are the three
surfaces above plus tests/stories that build `PropValueEditor` /
`EmptyTypedEditor` / `FieldValueStack` directly (noop `onZoomTo`).

## Gap 2 — one primitive, one hook, mutations stay on the surface

g2 measured four breaches inside a promoted `node-content.tsx` (`primitives
-> actions` and three `primitives -> stores`). The shape that closes them
without a `UI_ALLOWS` row:

- the primitive takes **everything** as props;
- store reads and store actions live in one hook under `stores/`;
- `mutations.attachFileToNode` / `mutations.removeTag` are passed by the
  surface, because no shared zone may import both `stores` and `actions`.

`components/outline/node-content.tsx` is a 24-line wrapper named `NodeContent`
so outline importers keep their import line. The `NodeTextHost` alias export
is dropped (that was the knip duplicate).

### `NodeTextHostBinding` as landed

```ts
export interface NodeTextHostBinding {
  nodes: NodeMap;
  zoomTo: (id: string) => void;
  pendingCaret: NodeTextHostPendingCaret | null;
  onRefClick: (e: React.MouseEvent, id: string) => void;
  consumeCaret: (instanceKey: string) => NodeTextHostPendingCaret | null;
  placeCaret: (instanceKey: string, at: NodeTextHostCaretAt) => void;
  selectNode: (id: string | null, instanceKey?: string) => void;
  registerTextHost: (instanceKey: string) => void;
  unregisterTextHost: (instanceKey: string) => void;
  setNodePaletteOpen: (open: boolean) => void;
  onAttachFile: (file: File) => void;
  onRemoveTag: (tagId: string) => void;
}
```

`NodeTextHostCaretAt` / `NodeTextHostPendingCaret` are unexported structural
twins of the store's `CaretIntent`. Exporting them made knip `types:` rise;
inlining the names on the binding would have been a second copy of the same
shape. The hook cannot import the type from the primitive (`stores` may not
import `primitives`); the outline/canvas wrappers are the composition site
and type-check the spread.

`useNodeTextHostBinding()` returns the store half (everything except
`onAttachFile` / `onRemoveTag`).

> **Coordinator fix-up at merge.** The branch's hook took `(nodeId,
> instanceKey)` and only handed them back — the brief had named that
> signature. Two parameters no code path reads are a declared abstraction
> nothing uses, so the merge drops them; the reads are store-wide and a
> node-scoped read belongs to the outline-store split, not to a parameter
> reserved for it.
