## One chord-matching mechanism

`lib/keychord.ts` (90 lines) is the only place that answers "does this event
match this chord". A chord is a set of *optional* constraints, so an absent
constraint is not asked about: `{ key: "Enter" }` claims Enter with or without
Shift, `{ alt: false }` claims only the unmodified form.

```ts
interface Chord { key?: KeyMatch; mod?: boolean; meta?: boolean; shift?: boolean; alt?: boolean }
lookupChord(ev, bindings, accepts?)   // first match wins
```

`mod` is `metaKey || ctrlKey`; `meta` is the literal Command key. Both exist
because the editing keymap genuinely distinguishes them — see the asymmetry
below — and `key` accepts a string, several spellings of one key, or a
predicate (`isPrintableKey`), which is what lets the printable fall-through be
a row rather than a `default:`.

`accepts` is the second half of a row's condition, for tables whose rows depend
on more than the event. Only the reference guard uses it.

### Editing mode — `components/outline/editing-keymap.ts`

The keymap sits on the outline surface rather than in `lib/` because it names
`VerticalNavDecision` from `./caret`, and a leaf zone may not import upward. It
reads the same `lib/keychord`, which is what gap 3 asked for.

Reference-instance guard (consulted first, only when `isRef`; a match means
"claim the key and do nothing"):

| chord | note |
|---|---|
| `⇥` | |
| `Enter` without Shift | `shift: false`, so ⇧Enter is *not* swallowed |
| `⌘/⌃ ⌫` or `⌘/⌃ ⌦` | claimed regardless of caret, unlike a plain row |
| `⌫` | only at offset 0 (`accepts`) |
| `⌘ ⇧ ↑/↓` | **`meta`, not `mod`** |

That last row is the asymmetry the old boolean expression buried: `⌘⇧↑`
reorders, so a reference swallows it, while `⌃⇧↑` means "collapse", which a
reference may do — it falls through to the reveal row below. Both spellings are
pinned in the characterization test.

Main table:

| # | chord | intent |
|---|---|---|
| 1 | `⇧Enter` | `softBreak` |
| 2 | `Enter` | `split` |
| 3 | `⇧⇥` | `outdent` |
| 4 | `⇥` | `indent` |
| 5 | `⌘/⌃ ⌫` | `deleteSubtree`, **only at offset 0** — mid-text stays native |
| 6 | `⌫` | offset 0 only: empty leaf → `deleteEmptyRow`; first child → `outdent` (D08); deeper → `mergeIntoPrevious` (D09); forest top edge → native |
| 7 | `⌘/⌃ ⌦` | `deleteSubtree` (no caret condition — the chain checked the modifier first here) |
| 8 | `⌦` | at end of text → `mergeNextIn` (F13), else native |
| 9 | `⌘⇧ ↑/↓` | `moveUp` / `moveDown` |
| 10 | `⌘/⌃ ↑/↓` | reveal: up closes an open parent else `zoomToParent`; down opens a closed row with children **or tags**; otherwise `claim` |
| 11 | `↑/↓` | `moveCaretToRow` when the caret is on the outermost visual line (D10/D11), else native |
| 12 | `Escape` | `select` |

Rows 5/7 are two rows rather than one because the chain read the caret before
the modifier for `⌫` and the modifier first for `⌦`. Putting the modifier in
the chord is what made that difference visible instead of implied.

Both dispatchers are `Record`-shaped, keyed by a mapped type over the union, so
a new action or intent with no row fails the build — no `default:`, no
exhaustiveness helper. The indexed call needs no cast because the dispatcher is
generic in the member's own `type`; that correlation is the only form of the
three I tried that TypeScript accepts.

## The command registry, and how the two palettes query it

`lib/commands.tsx` holds every command beside its implementation:

```ts
interface Command {
  id: string;
  scope: "global" | "node";
  chrome?: (ctx) => { label: string; icon: ReactNode };  // absent ⇒ a sys.command node names it
  when?: (ctx) => boolean;                               // absent ⇒ always offered
  run: (ctx) => void | Promise<void>;
}
```

`scope` carries the one real difference between the two kinds, and it is why
the shape is one shape:

- **global** — the 19 `sys.command` nodes. The node is the source of truth for
  title and keys, so those rows carry no `chrome`: the registry binds an id to
  a handler and restates nothing.
- **node** — the 16 rows of the ⌘K-on-a-row menu. Nothing in the graph names
  them, so they carry their own label and icon, and their position in the list
  *is* the menu order.

Two queries and a lookup:

- `runCommand(id, ctx)` — the ⌘K palette's `selectHit` and, through
  `NodeCommandListing.run`, the node menu's Enter. One lookup, one runner.
- `listNodeCommands(ctx)` — `scope === "node"` filtered by `when`, each row's
  `chrome` resolved and its `run` bound. The node menu renders exactly this.

The node menu used to be assembled by `base.push(...)` plus three
`base.splice(n, 0, …)` calls, so a row's index was a function of which
conditions fired. A static order plus `when` reproduces every combination —
verified by pinning the whole ordered label list for a plain node, a supertag,
a query node and a reference before touching anything.

`NodeCommandPalette` is now layout over that query plus one more table: a
`Picker` row per step (`add-tag`, `add-field`, `add-ref`) carrying its
placeholder, breadcrumb label, icon, candidate source and write. The three
parallel `step.type` ternaries — placeholder, step label, picker — collapsed
into that one record, and `pickerRows` builds the candidate list plus the mint
row outside the component.

One duplicate died on the way: the registry needed `WidthPref`, which was
declared in `stores/prefs.store`. Rather than a second copy in `lib/`, the type
moved to `lib/theme` beside `ThemePref` (with a `WIDTHS` tuple the store's zod
enum now reads) and `prefs.store` re-exports it. Two lines in a store file,
type-level only — flagging it since store changes are an owner call.

global command can reach it, but if the registry ever grows one, the fallback
is correct rather than silent.

## A gap I found and filed

`01M1XA98A0A7PWEPMHG2T4R5GP` — **concurrent ui test files share the store, so a
fire-and-forget write lands in another suite.**

Adding three DOM-driven suites made `bun run test:ui` intermittently red in
files I had not touched. It is not my refactor: vitest schedules the 105 UI
files across workers that share module state, and the outline's writes go
through `void mutations.X().then(…)` chains, so a chain still in flight when a
neighbouring suite asserts writes into *that* suite's store. Reproduced
directly: `use-node-keydown.characterization.test.tsx` paired with
`editor-behavior.test.tsx` is red under file parallelism and green with
`--no-file-parallelism`.

What I did about it: my suites drain their chains on both edges of a case
(`settle()` before the reset in `beforeEach`, `settle(8, 1)` in `afterEach`),
and the two assertions that depend on the row a caret lands on still being
reachable read the settled value rather than whichever tick they fell on. That
took my three files from "red roughly one run in three" to four consecutive
clean `bun run test:ui` runs (763/763 each). It fixes the within-file half only.

The cross-file half needs per-file isolation for the UI vitest project, or
mutations that return their focus hand-off instead of firing and forgetting.
`src/lib/palette-index.test.ts`'s `keystroke < 10ms` bar is the same hazard
measured by wall clock: 19ms under a loaded parallel run, green when run alone.
It tripped in three runs mid-wave and in none of the final four. Both are named
in the gap's `closes`.

I left both files alone — neither is mine, and the fix is a config or a
mutations-API change.

## Calls I made

- **The editing keymap lives in `components/outline/`, not `lib/`.** It must
  name `VerticalNavDecision`, which `./caret` owns, and the zone matrix forbids
  a leaf importing upward. The shared *mechanism* (`lib/keychord`) is what gap 3
  asked to be one thing, and it is.
- **`Chord` has both `mod` and `meta`.** Behaviour-preservation demanded it:
  the editing keymap's reorder row means the Command key literally, while its
  reveal row means either. One predicate, two questions it actually asks.
- **Dropped `useNodeKeyDown`'s `node` argument.** No code path read it, before
  or after; the context is read from the store, where the live row is. Three
  call sites and the test host updated.
- **`WidthPref` moved to `lib/theme`** rather than copied into the registry.
  Type-level, and `prefs.store` re-exports it — a store file change, hence
  flagged above.
- **Un-exported seven types from `lib/commands.tsx`** (`Command`,
  `CommandChrome`, `CommandScope`, `CommandTarget`, and the three store-API
  interfaces nothing outside names). Knip's ratchet caught them, and an export
  nothing reads is the dead seam Rule 1 names.
- **Reworded `GAP [[id]]` to `closed gap [[id]]`** in the doc comments that
  cite a gap this wave closed. The marker grammar should mean live debt.
- **`bun run harness:snapshot` twice**, for the `max-lines-per-function`
  warnings that left (35 → 33 → 31). The baseline was never hand-edited.
- **Left the two remaining thirds of gap 6, `kinds.test.ts`, the
  `palette-index` perf bar and the vitest isolation config alone**, and said so
  above rather than quietly widening the diff.
