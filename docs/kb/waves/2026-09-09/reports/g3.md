## Gaps 3 and 4: verified closed, not taken on trust

The brief said to check the code rather than the gap text. Both are closed by
u2 and nothing was left to finish:

- `onPointerMove` (`use-canvas-gestures.ts`) is four lines: it dispatches one
  `pointer/move` event carrying screen point, world point and `shiftKey`.
  Every drag kind is a state in `lib/canvas-pointer.ts`'s `Drag` union, and
  snapping is `snapCanvasMove`.
- `onPointerUp` (`createPointerEnd`) resolves the two facts only the DOM can
  answer for an edge drop — the card under the cursor, its world point — mints
  the two ids at the React boundary, and dispatches one `pointer/end`.
  `reduceEnd` is the same reducer's terminal transition, so the move and up
  paths can no longer disagree about what a drag kind means.

Both marked `status=done` with the closing note in `current`, following
`01M1MGT307N4K243CBPJTXNG5X`'s precedent ("Closed in f2. …").

Also recorded, because it is behaviour and not incidental: delete cascades to

does not (it is the select tool).

### The split (`74263f5`)

`lib/canvas-keymap.ts` — pure, no store, no ref, no DOM:

```ts
mapCanvasKey(event: CanvasKeyEvent, state: CanvasKeyState): CanvasKeyBinding | null
```

Eight sub-maps consulted in `CHORD_MAPS` order, which is the original
`handleKeyDown` order unchanged and now visible as data. `CanvasIntent` has 14
members; `CanvasKeyBinding` is `{ intent: CanvasIntent | null; preventDefault:
boolean }`, which is how the two quirks stopped being control flow:

- `intent: null` is *claimed with nothing to do* — a selection-only command
  pressed with nothing selected — as distinct from claiming nothing at all
  (outer `null`).
- `preventDefault` is a property of the binding, so Escape and the
  empty-selection arrow keep handing the key to the browser without a special
  case at the listener.

`components/canvas/use-canvas-keyboard.ts` keeps the effects: eight named
appliers and one exhaustive `applyCanvasIntent` over the intent union
(`switch-exhaustiveness-check` turns a new intent without a case red). The
listener is six lines between the two. `lib/canvas-keymap.test.ts` adds 36
tests over the map with no DOM at all.

One Rule 1 collapse taken on the way: `MIN_ZOOM`/`MAX_ZOOM`/the 1.15 step were
declared twice, once in each canvas hook. They now live in
`lib/canvas-viewport.ts` as `clampZoom` and `ZOOM_STEP` and both callers read
them. The keymap's zoom now clamps both ways where it previously clamped one —
equivalent, since a zoom-in from at-or-above the minimum could never reach it,
and the wheel already clamped both ways.

## Gap 6: one edge-relink planner

`changeEdgeMode` and `changeEdgeField` were two near-copies of one
transformation: resolve the endpoints, settle a `kbLink`, validate the native
target, plan the one-shot prop write, persist. The gap asked for a named
`(edge, mode) -> plan`; taking only the mode half would have left the copy in
place, so both go through one planner.

`lib/canvas-edge-link.ts`:

```ts
type EdgeRelink = { kind: "mode"; mode: KbLinkMode } | { kind: "field"; fieldId: string };
type EdgeRelinkPlan =
  | { kind: "none" } | { kind: "reject"; reason: string }
  | { kind: "write"; edge: CanvasEdge; props?: EdgePropWrite };
planEdgeRelink(edge, change, ctx): EdgeRelinkPlan
```

Pure: the fresh binding id arrives on `ctx`, the way the pointer reducer takes
its edge ids. `use-canvas-edge-actions.ts` is now one `relinkEdge` applier —
toast, nothing, or one atomic `flushPersist` — and both callbacks are one line.

Behaviour-preserving, quirks included and now tested (13 tests):

- native is refused on an edge with **no `kbLink` at all** before endpoints are
  even resolved (`edge.kbLink?.fieldId === undefined` is only true when the
  link is absent, since `KbLink.fieldId` is a required `string`);
- a drawing between cards that are not kb nodes moves only its mode, and
  native-without-a-field silently downgrades to `layout`;
- a field change on such an edge does nothing at all (no toast, no write);
- the inspector's `<option value="">Select field…</option>` still falls through
  to "Target not allowed for this ref field" rather than the needs-a-field
  message — the two paths reject differently and that is preserved;
- the prop write is skipped when the source already holds the ref triple.

`deleteEdge` was left alone: its gap is not in this wave and it carries a
`window.confirm`, so it is an effect, not a plan.

## Gap 7: blocked, not skipped

`components/canvas/canvas-card.tsx` imports `NodeContent` from
`components/outline/node-content.tsx` under
`// GAP [[01M1RXNGSJT2J2VHDSYY7QJSD3]]`. The brief suggested promoting "the
read-only part the card needs". That part does not exist as a seam: the canvas
card is a **full editor**. It passes `isActive`, `onActivate` and `onChange`,
and `KbNodeCard` has its own `handleCanvasNodeKeyDown`, so the card takes the
`contentEditable` branch of `NodeTextHost` whenever the node is active.
Promoting only the read-only half would delete canvas card text editing.

The whole component is the right thing to promote — the file already calls
itself "the common text host", `NodeContent` is a compatibility alias for
`NodeTextHost`, and the outline, the zoomed root header, the table and board
views and the canvas card all use it. I ran that move to find out what it
costs: `git mv` to `components/ui/node-text-host.tsx`, imports rewired in all
six call sites, then `bun test harness/tests/ui-boundaries.test.ts`:

```text
packages/app/ui/src/components/ui/node-text-host.tsx:3:  primitives -> actions
packages/app/ui/src/components/ui/node-text-host.tsx:14: primitives -> stores
packages/app/ui/src/components/ui/node-text-host.tsx:15: primitives -> stores
packages/app/ui/src/components/ui/node-text-host.tsx:16: primitives -> components/outline
packages/app/ui/src/components/ui/node-text-host.tsx:19: primitives -> components/outline
(fail) ui-boundaries > every import inside the UI lands in a zone its importer may reach
```

Five new breaches for one closed. `UI_ALLOWS` gives `primitives` only
`["primitives", "lib"]`, and the trade is worse than the gap:

| breach | what it needs | who owns it |
|---|---|---|
| `-> actions` (`mutations.attachFileToNode`, `removeTag`) | a `UI_ALLOWS` row, or the calls lifted to props | `constraints.ts` — **not g3** |
| `-> stores` ×2 (`outline.store`, `ui.store`) | exactly gap `01M1RXMRJA3ZRAWPTB0ZH5YEYG`, "the field-value primitive subscribes to the outline store", whose `closes` says it lands with the outline-store split | that gap |
| `-> components/outline` (`md-view`) | gap `01M1RXNKKK31EGJWCA1KCV6V20`, "move MdView into the primitives zone" — **batch 2, g2** | g2 |
| `-> components/outline` (`./caret`) | `caret.ts` promoted too; no gap exists for it | unfiled |

I reverted the move and left the marker on the import. Adding a
`primitives -> stores, actions` row would silently legalise the field-value
gap the repo is deliberately holding open, and marking four fresh breaches
would trade one recorded gap for three unrecorded ones — either is drift, so I
stopped, as the brief directs. Also note `harness/lint-warn-baseline.json`
carries
`duplicates:…/node-content.tsx:NodeContent|NodeTextHost`, so whoever lands the
move should drop the alias in the same change and re-snapshot.

**Recommended order:** g2's MdView promotion, then `caret.ts`, then a decision
on `01M1RXMRJA3ZRAWPTB0ZH5YEYG`; gap 7 falls out afterwards as a rename.

## Calls I made

- **Commit 1 is `test(kb-ui):`, not `fix(kb-ui):`.** The two bugs were already
  fixed on the branch. Writing "fix" would have claimed work origin did.
- **Split the characterization into its own commit** ahead of the keydown
  refactor, so "passes unchanged" is checkable from the history rather than
  asserted.
- **Gap 6 covers `changeEdgeField` too.** Planning only the mode change would
  have left its near-copy beside it, which is the shape Rule 1 names.
- **`CanvasKeyBinding` carries `preventDefault`** instead of the applier
  inferring it. The alternative — an `if` for Escape and another for the empty
  arrow — is special-casing at the call site.
- **Collapsed the duplicated zoom bounds** into `lib/canvas-viewport.ts` while
  in the file. In scope (`lib/canvas-*`), and leaving two copies while
  extracting the keymap from one of them would have been the mirror Rule 1
  forbids.
- **New file named `lib/canvas-keymap.ts`.** It matches g3's `lib/canvas-*`
  zone and also g4's `lib/*keymap*` glob; it is a new file, so no edit
  overlaps g4, but the name is flagged here in case the coordinator prefers
  another.
- **Left `docs/kb/todos.md` untouched**; `docs.materialize` rewrote only
  `docs/kb/rules.md`, where the six closed gaps move into the done section.
