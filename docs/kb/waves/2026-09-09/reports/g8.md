## 1. The Schema shapes

The gap asked for "one Schema". What the two configs actually share is not one
schema but **one mechanism**, because they decode different shapes from the
same kind of carrier. `@kb/model/src/node-config.ts` is that mechanism; each
config declares a slot table against it, beside the type it produces.

### The mechanism

```ts
interface ConfigSlot<A> {
  readonly fields: readonly NodeId[];                        // which field nodes it reads
  readonly decode: (props: NodeProps) => SlotDecode<A>;      // built by oneOf / manyOf
}

type ConfigSlots<T> = { readonly [K in keyof T]-?: ConfigSlot<T[K]> };
type ConfigReader<T> = <K extends keyof T>(key: K) => T[K];

function decodeNodeConfig<T extends object>(
  slots: ConfigSlots<T>,
  props: NodeProps | undefined,
  report: (warning: string) => void,
): ConfigReader<T>;
```

Two questions are deliberately kept apart, and that separation is the whole
design:

- **Which stored values does this slot read?** A *carrier* question, answered
  by a reader: `firstStr` / `firstNum` / `firstBool` / `firstRef` /
  `allValues`, plus the config's own (`sourceKey`, `rendererKey`,
  `sortSpecValues`, `colwidthValue`, …). kb props are multi-valued and untyped
  per value, so "the first `num` value of `lens.max-nodes`" is a projection,
  not a validation.
- **Is what it read a legal value?** A *validity* question, answered by an
  Effect `Schema`. The slot names the value used when the store says nothing,
  so a default sits beside the shape it defaults to and has exactly one home.

Props are multi-valued, so a slot has two constructors — not a boolean, not a
flag:

| | reads | element rule |
|---|---|---|
| `oneOf` | one value of one field | reader returns `undefined` for "nothing readable" |
| `manyOf` | every value of a field (or of a paired set) | an element decoding to `null` contributes nothing |

`decodeNodeConfig` returns a **reader**, not a finished object. That is
deliberate twice over: a mapped-type product cannot be assembled from
`Object.entries` without an unchecked assertion (`no-unsafe-type-assertion` is
`error` here, and the brief forbids new disables), and the caller listing its
keys is what makes TypeScript prove the config complete. That completeness is
also what makes the report complete — each slot is decoded exactly once, on
the way to the field it fills, and reports as it goes. `report` is a required
parameter, not an optional one with a no-op default: where a malformed prop
goes is a decision each surface has to make.

```ts
const EdgeKindSchema = Schema.Union([
  Schema.Literals(["mention", "child", "ref-prop"]),
  Schema.String.pipe(Schema.refine((k): k is `prop:${string}` => k.startsWith("prop:"), {
    expected: 'a "prop:<field id>" key',
  })),
]);                                        // exactly the EdgeKind type, as a schema

const NodeCountSchema = Schema.Finite.check(Schema.isGreaterThan(0)).pipe(
  Schema.decodeTo(Schema.Number, {         // positive, and whole however it was stored
    decode: SchemaGetter.transform((v: number) => Math.floor(v)),
    encode: SchemaGetter.transform((v: number) => v),
  }),
);

const SourceSchema = Schema.String;        // free-form on purpose (g1: a key kb
                                           // does not know is a user field)
```

a node reference (post-g1), a legacy key string, and a `prop:<field id>`
string that no option covers:

```ts
const sourceKey = (field: string) => (props: NodeProps): string | undefined => {
  const first = props[field]?.[0];
  return first?.t === "ref" ? graphSourceKey(first.v) : firstStr(field)(props);

```

### On the seed's defaults (gap 2's second half)

The gap says defaults are "duplicated between this function and the ontology".
Checked: the seed declares **no** defaults for `sys.f.view.*` — `seed.ts` mints
the eight field nodes with nothing but `sys.f.type` — so there was no seed

and `DEFAULT_VIEW_CONFIG`, and it is gone: the slot table reads
`DEFAULT_VIEW_CONFIG`.

The lens side is the same: `seed.ts` mints the lens field nodes and one
*perspective* node (`lens.all-mentions`) whose props are chosen values, not
declared defaults. `ensureSystemSeed`'s fill-absent-props pass copies those
onto older stores, which is a seeding rule, not a second default table.

### Where the mechanism lives, and why not more

The mechanism is in `@kb/model` (a props record and a field-node id are domain
concepts, and `@kb/ui`'s `lib` may import `@kb/model` — `graph-lens.ts` already
did). The **slot tables** stayed beside the types they produce rather than
moving into a new module each, because the two configs now share their decoder
and a third file per config would be a home for nothing. Moving
`LensPerspective` wholesale into `@kb/model` — the brief floats it as "the
cleaner home" — would drag `EdgeKind`, `LensLayout`, `LensLabelDensity` and
their component consumers with it; recorded as an option, not taken.

## 2. The malformed-input policy, and where a warning surfaces

Stated once in `node-config.ts` and again in `DESIGN.md` → *Domain typing*:

- **Absent prop → unset.** The declared default applies, silently. A prop the
  store never carried is not a mistake.
- **Present prop the slot cannot read → malformed.** Wrong carrier, or a value
  the schema rejects: the same default applies **and is reported**, naming the
  field node and what was expected. Nothing throws — a bad prop must never
  make a graph or an outline unopenable.
- **Multi-valued field → per value.** One bad clause is reported by its index
  and the readable ones survive. **Single-valued field → whole.** It is one
  value; it is legal or it is not.
- **An element that decodes to `null` contributes nothing, unreported.** That
  is how a documented sentinel says "explicitly empty": `sys.graph.source.none`
  stored in `lens.edge-kinds` means *no edges* (g1's report explains why the
  panel writes it), and is a value, not a typo.

Sample reports, as emitted:

```
[graph-lens] lens.p: sys.f.lens.layout ignored: Expected "force" | "radial" | "hierarchical" | "grid"
[graph-lens] lens.p: sys.f.lens.show-labels ignored: no readable value
[graph-lens] lens.p: sys.f.lens.edge-kinds[1] ignored: Expected "mention" | "child" | "ref-prop" | a "prop:<field id>" key
[view-config] sys.f.view.mode ignored: Expected "list" | "table" | "board" | "cards"
[view-config] sys.f.view.sort + sys.f.view.sort.dir[0] ignored: ...
```

**Where it surfaces, honestly:** `@kb/ui`'s log seam (`lib/log`), which is the
one diagnostic output the package has and is where `getViewConfig`'s single
bespoke `logWarn` already went. It replaces that one, so there is one channel,
not two.

It is **not** surfaced in the UI the way `resolveOntology`'s warnings are
(`ontology-scope-bar`'s badge, fed from `outline.store.ontologyWarnings`).
Reaching that needs a store field and a component, both of which g8's brief
puts out of zone ("A store API change or a component change: no — report").

I also deliberately did **not** add a `warnings: string[]` to `LensPerspective`
and `ViewConfig`, which is the brief's suggested shape. With no component
reading it, that field would be a declared abstraction no code path reads —
the dead seam Rule 1 calls "still a duplicate". It is also the wrong type
design: `LensPerspective` round-trips through `perspectiveProps` back into node
props, and a decode diagnostic is not part of a perspective. Filed instead:

> `01M1XF1NA2RBAX1E6NNX6PMZ6N` — **GAP: node-config decode warnings reach the
> browser log, not the UI.** `closes`: give the two decoders' reports a home in
> the ui the way ontology warnings have one — a store field plus a badge — and
> have the config surfaces read it instead of the log seam.

Its `impact` records the second half of the cost: `getViewConfig` runs per node
per render, so a malformed view prop re-logs. That is not a regression (the
bad-filter-EDN `logWarn` behaved identically), but it is a reason the badge is
the right destination.

## 4. How `order`'s absence is expressed now

`9d8e111` (before this wave) had already done the gap's first half —
`KbNodeSchema.order` is declared. The gap's `current` text was therefore stale
when I read it ("absent from `KbNodeSchema` entirely"), and its `impact` — a
stricter backend dropping the field — was already closed. What was left is the
half `closes` names: *"encode the migration state as a discriminator instead of
an optional field"*.

**The migration state is a property of a node set, not of a field.** A stored
row minted before fractional ordering has no rank and the canonical writer must
not invent one — so absence is a real stored state. But no *live* node is in
it: `openKbEffect` is the single open path and it runs `migrateOrderKeys`
before anything else sees the nodes. So the discriminator is **which of two
types** a node has:

```ts
// model.ts
export type RankedNode = KbNode & { order: string };

// order.ts
export type NodeRank =
  | { readonly ranked: true; readonly order: string }
  | { readonly ranked: false };

export function rankOf(node: { readonly order?: string } | undefined): NodeRank;
export function isRanked(node: KbNode): node is RankedNode;   // the same question, as a narrowing

export function migrateOrderKeys(nodes: KbNode[]): { nodes: RankedNode[]; changed: boolean };
```

`migrateOrderKeys`' postcondition is now in its signature and proven by
construction, not asserted: every node belongs to exactly one sibling group
(its parent's `children`, or the forest root) and the loop leaves every group
fully ranked, so the already-ranked branch returns the node *by identity*
(`isRanked` narrows it) and the other branch's rank is `present(…)`. One
`present` call states the invariant instead of widening the result back to
"maybe unranked". Cast-free; `no-unsafe-type-assertion` stays clean.

`KbNodeSchema.order` becomes `optionalKey(NonEmptyString)`. That is what makes
`rankOf` **one** test rather than two: absence is now the only way to be
unranked, so `""` is not a second spelling of the same state. Before this, the
codebase disagreed with itself — `order.ts` treated `""` as unranked,
`mutations.ts` and `graph-view.ts` treated it as ranked.

Both committed stores are already fully ranked, so no data moves and the
byte-exact round trip is untouched:

```
.kb/nodes.jsonl        total 404  no-order 0  empty 0
tools/kb/.kb/nodes.jsonl total  95  no-order 0  empty 0
```

## 7. Calls I made

1. **One mechanism in `@kb/model`, two slot tables in place.** The brief
   offered "a schema module beside each, or one shared module if the two share
   a decoder". They do share a decoder, so a third file per config would own
   nothing. §1.
2. **Two slot constructors, `oneOf` and `manyOf`.** Not a flag on one
   constructor. kb props are multi-valued by nature, so "is this field read as
   one value or as many" is a fact about the field, and Rule 1 says such a
   distinction belongs in the type, not at the call site. It is also what lets
   one bad filter clause drop without taking the others.
3. **The sentinel is `null`, not a hook.** `manyOf` could have taken an
   `isSentinel` predicate for `lens.edge-kinds`' `none`. Instead an element
   that decodes to `null` contributes nothing, and the `none → null` mapping
   lives in the edge-kinds reader where it belongs. One rule, no optional hook
   used once.
4. **`decodeNodeConfig` returns a reader and takes a report sink.** Forced by
   `no-unsafe-type-assertion` (a mapped-type product needs a cast) and by not
   wanting to decode every slot twice. The side benefit is that `report` is
   required, so no surface can be written that silently swallows. §1.
5. **No `warnings` field on `LensPerspective` / `ViewConfig`.** The brief
   recommends one; with no component reading it, it would be a dead seam, and a
   decode diagnostic is not part of a perspective that round-trips back to node
   props. `logWarn` + gap `01M1XF1NA2RBAX1E6NNX6PMZ6N` instead. §2.
6. **`colwidth` falls back whole.** The stated policy is per *field*, and this
   field is one JSON value. Two existing tests updated with the reasoning
   written into them. §3.
