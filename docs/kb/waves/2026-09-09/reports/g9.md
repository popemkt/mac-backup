## Gap 2 — the import graph sees every edge

`importEdges` filtered on `/^@kb\/[a-z0-9-]+$/` over the **raw specifier**,
and `sourceFilesUnder` scanned `.ts`/`.tsx`. Four fences read that graph —
layer, scope, isomorphism, public-surface — so all four could be crossed by
choosing a spelling.

### The shape

One resolver, `resolveImport`, answers *which package does this specifier
reach, and by what name*:

| target | meaning |
|---|---|
| `internal` | its own package — own name, a relative path that stays in, an alias that stays in |
| `third-party` | npm, `node:`, `bun:` |
| `workspace` + `form: entry` | the bare package name — the only sanctioned spelling |
| `workspace` + `form: subpath` | `@kb/<pkg>/…` — past the barrel |
| `workspace` + `form: relative` | a relative path that leaves the package — never names the target |
| `escape` | a relative path landing under no package at all |

`resolvedImports()` is that one pass; `importEdges()` filters it for
`boundaries`, and `surfaceBypass()` says why a non-`entry` form is a breach
for `public-surface`, which is where "the barrel *is* the surface" already
lives. `SOURCE_EXT` is now the whole JavaScript family —
`.ts .tsx .mts .cts .js .jsx .mjs .cjs`, two more than the brief listed,
because `.mjs`/`.cjs` are the same blind spot and leaving them out would
re-open it.

A package's own tsconfig `paths` are expanded before resolution. `@kb/ui`'s
`@/*` → `./src/*` is the only one today, and read as a bare specifier it looks
third-party; an alias retargeted at another package would have been an edge
nothing could see.

### Two Rule-1 moves, both collapsing a duplicate

- The direction rule was inline in `boundaries.test.ts`. It moved to
  `constraints.matrixViolation` so the fixtures measure edges against the same
  matrix the real check does, rather than a copy. **No matrix row changed** —
  `LAYER_ALLOWS`, `SCOPE_ALLOWS`, `UI_ALLOWS` are byte-identical.
- The axes map moved to `workspace.packageAxes`, next to the manifests it is
  read from.
- Every workspace reader (`layerDirs`, `packageDirs`, `workspacePackages`,
  `importSites`, `resolvedImports`, `importEdges`) now takes a packages root,
  defaulting to this workspace's. That is what lets a fixture be a real
  two-package tree run through the *real* functions instead of a test-only
  reimplementation.

`packageRoots`, `resolveImport`, `PackageRoot`, `ImportForm` and `ImportTarget`
are deliberately **not** exported: knip flagged all five as unread the moment
they were, and an export nothing reads is dead. Consumers go through
`resolvedImports` / `importEdges` / `surfaceBypass`.

or two source files per package — with `domain/low` (`scope:shared`) and
`app/high` (`scope:backend`) chosen so a single edge breaches **both** matrix
axes. 21 tests in `harness/tests/import-graph.test.ts` (6 pre-existing + 15
new, 8 of which are the extension cases).

## Gap 3 — admission reads what will be committed

`intent/gate.sh record` already reconstructed the index for its Nix lane. The
hook's own three checks — generated docs, `.kb/assets` ownership, `bun run
verify` — read the **working tree**, and its kb trigger was `^tools/kb/`
alone.

### The snapshot mechanism

A **detached linked worktree of `git write-tree`**:

```
tree=$(git write-tree)                                 # the staged tree
commit=$(git commit-tree "$tree" -m 'pre-commit index snapshot')
git worktree add --detach --quiet "$snapshot" "$commit"
```

`git checkout-index` into a plain directory was tried first and is **not
enough**: the harness reads the tree through `git ls-files` and
`git check-ignore`, so a non-repository snapshot fails 8 of its own checks for
the wrong reason (`lint-scope-coverage`, `typecheck-scope`, `skip-pairing`,
`no-conflict-markers`, `gitignore-covers-derived`, `tsconfig-presets`,
`suppression grammar`, `gap-markers-resolve`). `git stash --keep-index` was
never a candidate — it moves the user's tree.

**`node_modules` is borrowed, not installed.** The content-addressed store
(`node_modules/.bun`) and the caches are absolute symlinks to the checkout;
everything else in each `node_modules` tree is already a symlink and is copied
*as* one, by a single `tar` pipe. That distinction is the whole trick: a
package's `node_modules/@kb/<member>` link is **relative** to a sibling source
directory, so copied it resolves inside the snapshot, and shared it would
resolve back into the working tree — and the hook would have checked the wrong
files while looking like it worked.

### The trap that nearly shipped

The first version of this hook **failed its own commit**, and the reason is
worth recording: git exports `GIT_DIR` and `GIT_INDEX_FILE` into a hook, and
they name the committing repository. `git worktree add` inheriting
`GIT_INDEX_FILE` checks the files out **but leaves the new worktree's index
empty**. `git ls-files` in the snapshot then returns nothing, and every
tree-reading check passes on **no files at all** — a green hook that checked
nothing. Only `tsconfig-presets` caught it, because it is the one check that
asserts a *non-empty* result:

```
error: @effect/language-service appears in:
- [ "tsconfig.iso.json" ]
+ []
```

Fixed two ways: every snapshot-directed git command runs through
`env -u GIT_DIR -u GIT_WORK_TREE -u GIT_INDEX_FILE -u GIT_PREFIX`, and the
hook then **asserts the invariant** rather than trusting it —
`git -C "$snapshot" diff --cached --quiet HEAD`, which fails loudly on an
empty index. `git write-tree` deliberately keeps the hook's own env, because
the index being committed is exactly what it must read.

### Triggers

One table, each check against its own inputs (stated at the trigger site and
tabulated in `docs/ci.md`):

| check | staged paths |
|---|---|
| generated docs (`docs-check.ts`) | `.kb/**`, `docs/kb/**`, `tools/kb/**` |
| `.kb/assets` ownership | `.kb/**`, `.gitignore`, `docs/backup-strategy.md`, `modules/darwin/home-manager/mackup.nix`, `scripts/check-kb-assets-backup.sh` |

`verify`'s row is the brief's list, and it is derived rather than guessed:
`verify` ends in `bun run check:audit`, and `ext.check.audit` reads every
`#rule`'s `home`, every `#check`'s `evidence`, and `@kb/ext-check`'s
`SURFACE_FILES`. I enumerated those values out of `.kb/nodes.jsonl` —
`CLAUDE.md#…`, `tools/kb/AGENTS.md#…`, `tools/kb/DESIGN.md#…`,
`tools/kb/harness/tests/*.ts`, `tools/kb/.oxlintrc.json`,
`docs/kb/waves/…` — and every one falls inside that row. The
`SURFACE_FILES` entries for the `hook` and `ci` surfaces are
`.githooks/pre-commit` and `.github/workflows/*.yml`; both keep their
invocation strings (`docs-check.ts`, `intent/gate.sh`) in the new hook, and
`ext.check.audit` reports `kb checks: clean` on the snapshot that contains it.

The docs and assets checks **narrowed** — they ran on every commit before.
That is not a loss: in the snapshot their inputs are at HEAD unless staged, so
the answer was already known.

`intent/gate.sh` is untouched. It keeps its own `checkout-index` snapshot,
which reads as a duplicate but is not: that one feeds
`nix flake check "path:…"`, which copies the whole directory into the store,
so it has to stay a pristine ~9 MB checkout with no `node_modules`. One index,
two shapes, each built where its requirement is stated — written down in both
files so a reader does not have to guess.

## Calls I made

- **The 4 trailing `oxlint-disable-line` comments are sites to fix, not a form
  to accept.** `CLAUDE.md` states one form; two positions for the same
  sanction is a second grammar, and the checker already rejected them. Moving
  them costs +1 line each.
- **Folded three prose comment lines into the directive reason** (and one in
  `board-cards-view.tsx`) rather than leaving both. The grammar demands a
  reason, so the directive is now that reason's one home; keeping the prose
  line too is the restatement `CLAUDE.md` calls drift.
- **`.mjs`/`.cjs` added beyond the brief's four extensions.** The same blind
  spot; enumerating six of eight would leave the gap half open.
- **Added `matrixViolation` to `constraints.ts`.** Not a matrix change — the
  three matrices are byte-identical. It collapses the direction rule that was
  duplicated between `boundaries.test.ts` and (would have been) the fixtures.
- **Parameterized the workspace readers by packages root** instead of writing
  fixture-only readers. A fixture that exercises a copy of the reader proves
  nothing about the reader.
- **Did not touch `intent/gate.sh`.** Its snapshot has a different contract
  (pristine, `path:`-copyable). Reasoned above and in `docs/ci.md`; it is not
  in this brief's ownership either way.
- **Left `CLAUDE.md`'s two pre-commit sentences alone.** Both are still true
  and neither states a trigger; the trigger list's one home is `docs/ci.md`,
  which `tools/kb/AGENTS.md` now links to rather than restating.
