## What each move actually cost, and the three gaps whose text was wrong

Two gap descriptions and one `closes` did not survive contact with the code.
Each is called out where it changed the shape of the fix.

### Gap 1 — `MdView` was not store-free

The gap says "it takes text and options and touches no store". It read
`zoomTo` and `jumpToNode` off the outline store to handle a click on an inline
`[[id]]` ref, and `components/ui/` holds nothing that reads a store — every
primitive there (`EnumSelect`, `PopoverShell`, `ThemeIcon`, `WorkspaceState`,
`WorkspaceBoundary`) is props-in, and the `primitives` row is
`["primitives", "lib"]`.

So the handler became an `onRefClick` prop, exactly the shape `TagChip`'s
`onClick` and `NodeRow`'s `onRowClick` already have, and it is **required**:
optional would let a call site silently fall back to the browser's
`href="#id"` navigation. `stores/ref-navigation.ts` owns the one handler
(zoom, or `jumpToNode` when meta/ctrl is held); all four call sites are
surfaces, so all four may read it — `components/ontology/member-row.tsx`,
`components/outline/{node-content,references-section,schema-section}.tsx`.

### Gap 2 — filed, then closed

Filed as `01M1XCB0ETCJH03FGJS6E75AFP` before the move, in the same commit as
the brief allows. `caret.ts` is pure DOM math over a contenteditable and
imports only `lib/dom` and `lib/md-edit`, so it went to `lib/caret.ts` with its
colocated test. Its three importers — `node-content.tsx`, `use-node-keydown.ts`
and g4's `editing-keymap.ts` (the `VerticalNavDecision` type-only import the
brief flagged) — are one-line path changes.

### Gap 3 — the picker is genuinely a primitive, so option A

The brief said to prefer "App passes the chosen ontology down" unless the
picker is genuinely a primitive. It is: props in, no store, and its only
imports are React, `@phosphor-icons/react`, `lib/cn` and one `lib` type.

The App option also does not apply on inspection. `GraphPage` already *takes*
`ontologyId` as a prop; what it reached across for is the control that
**changes** it, sitting in the graph header next to `PerspectivePicker` and
`RendererSwitch`. Lifting that control to App would move it out of the header —
a layout change, not a behaviour-preserving move. So
`components/ontology/ontology-picker.tsx` -> `components/ui/ontology-picker.tsx`.

Noted, not acted on: `components/graph/perspective-picker.tsx` is the same
popover-list anatomy (its own comment says so) with a save form and a
`mutations` call bolted on, which is why it is *not* a primitive. One shared
picker shell with the form as a slot looks like a real collapse, but it is a
different unit's contract and no gap names it.

### Gap 4 — the toggle is a primitive plus a store hook

`SidebarToggle` read `usePrefsStore` for `sidebarOpen`/`toggleSidebar`, so the
same constraint as gap 1 applies. It became
`components/ui/sidebar-toggle.tsx` taking `open` and `onToggle`, and
`useSidebarToggle` on `stores/prefs.store.ts` owns both — beside `useDarkTheme`,
which is the existing precedent for a derived hook in that module, rather than
a new file.

The focus hand-off stayed with the hook, not the button: it exists because
collapsing a sidebar that holds focus would drop focus on the document, which
is a fact about the panel. `onToggle` receives the button so the hook can hand
focus back. `lib/dom.ts` now owns the panel's marker attribute in both forms
(`sidebarRegionProps` to spread, `SIDEBAR_REGION_SELECTOR` to query) so the
sidebar that writes it and the hook that reads it share one string instead of
two copies of `data-sidebar="true"`.

Both call sites — `components/App.tsx` (shell) and `graph-page.tsx` — are now
`<SidebarToggle {...sidebar} />`.

### Gap 6 — the second close was not available

The brief preferred "drop the fixture fallback and let the caller decide"
if nothing in production relies on the fixture's content. Production does:

- `VITE_USE_FIXTURES=1 bun run dev` is documented in `packages/app/ui/README.md`
  and forces the snapshot;
- `loadGraph` falls back to it at cold boot, and the store records
  `loadSource: "fixtures"`, which `actions/mutations.ts` (three sites) and
  `actions/optimistic.ts` read to keep every write local. `git log` shows the
  fallback was deliberately *narrowed* in `05e53d0`
  ("stop fixture hydration on failed mid-session resync") rather than removed —
  strict `fetchGraphSnapshot` never serves it; only cold boot does.

Handing the decision to the caller does not close the breach either: the caller
is `components/App.tsx`, and `shell` has no `fixtures` row. Under `UI_ALLOWS`
**no production zone may reach that folder at all** — `fixtures`' row is
`["fixtures", "lib"]`, which is what it may import, not who may import it. So
the data has to leave the folder.

`fixtures/graph.ts` -> `api/fixture-graph.ts`, beside the transport that serves
it, with a header stating that it is product code and that the `fixtures/`
folder next door is test-only. The export keeps the name `fixtureGraph` because
the product's own vocabulary is "fixtures": the `GraphLoadSource` union, the
store's `loadSource`, and the `rev N · fixtures` readout in the header.
37 test files follow the path (one `sed`, no assertions touched);
`fixtures/contextual-ref.ts` and `fixtures/view-fields.ts` stay, so the zone
still exists and `UI_ALLOWS` still matches the tree.

### Gaps 7+8 — one hook and one pure function

- `lib/backlinks.ts` owns "the nodes that reference X, as rows": the `ds/`
  query plus the display rule that a referrer with empty text shows its
  contextual text. `BacklinkRow` moved with it. `ReferencesSection` keeps its
  `useMemo` (and its existing `exhaustive-deps` disable, unchanged) and
  renders; `ReferencesView` still takes rows as props, so its test is
  untouched.
- `lib/use-query-node-rows.ts` owns a query node's current rows from whichever
  source can answer — the `/ws` subscription while the socket is open, the
  local index otherwise. It holds the `useEffect` that opens and closes the
  subscription and the `useMemo` that runs datalog (with the disable comment
  that came with that code). `QueryResultsSection` now reads
  `{ rows, error }` and renders.

`lib/query-node.ts` stays what its header claims to be — pure system-node
modeling — which is why the hook is a sibling module rather than an addition to
it. `lib` may reach `api` and `ds`, so neither module needs a new row.

Neither test changed: `query-results.test.tsx` and `references-section.test.tsx`
drive `@/ds` directly, which test files may.

### Gap 9 — the `closes` inverts, provably

The gap's `closes` says "toast moves onto `ui.store`'s own surface". That is
not reachable, and the matrix proves it rather than suggesting it. `toast()` is
called from `stores/outline.store`, `components/{canvas,outline,palette}`,
`actions/{mutations,optimistic}`, `lib/commands` and `session/runtime`.
Intersecting the `UI_ALLOWS` rows of those zones leaves exactly one target
zone: **`lib`**. `actions`, `session` and `lib` have no `stores` row; a surface
has no `api` row. Moving the function onto the store would turn one breach into
four.

So the direction inverts: `lib/toast.ts` declares the sink
(`setToastSink` / `toast`) and `stores/ui.store.ts` registers itself at module
scope — `stores -> lib`, the direction every other row states. Registration is
module scope rather than a boot step because every path that can render a toast
already imports that module (App renders `<Toasts/>` from it), and with no sink
the message is logged through `lib/log` rather than dropped silently, so the
hole would be visible if the wiring ever broke. The five test files that assert
on `useUiStore.getState().toasts` all import the store, so all of them still
see real toasts; no "no sink registered" line appears in any suite run.

`lib/canvas-api.ts` typed one parameter as
`ReturnType<typeof useOutlineStore.getState>["index"]`, importing the whole
store for a type. It is `KbIndex | null` from `@/ds` — the same type
`resolveAllowedRefIds`, which that function calls, already takes. Its two
callers derive their own parameter types from this signature
(`Parameters<typeof isValidNativeTarget>[3]`), so nothing else moved. The
gap's `closes` says canvas-api should "take the node map"; it already takes the
node map, and the store dependency was the index type.

## Calls I made

1. **`MdView`'s `onRefClick` is required, not optional.** An optional prop
   would let a fifth call site render refs that navigate by `href="#id"`
   instead of zooming, and nothing would catch it. Required makes the compiler
   the check. Cost: four call sites each gained one hook line.
2. **`stores/ref-navigation.ts` is a new file, not an addition to
   `outline.store.ts`.** One concept, one module, and it keeps g5/g7 out of a
   merge conflict in a 27 KB store file they are both editing.
3. **`useSidebarToggle` went *into* `stores/prefs.store.ts`.** The opposite
   call from (2), because `useDarkTheme` is already there: a derived hook on
   the prefs store has an established home, and a second module for one of them
   would be the parallel path Rule 1 warns about.
4. **`lib/dom.ts` owns `data-sidebar` in two derived forms.** The alternative
   was the literal in both the sidebar and the toggle's caller, which is a
   mirror. `lib/dom.ts` is described as "the DOM boundary", so it is the right
   owner rather than a new module.
5. **The `fixtureGraph` export kept its name.** Renaming it to `demoGraph`
   while `GraphLoadSource`, `loadSource` and the header readout all say
   "fixtures" would split the product's vocabulary for no gain. The module name
   (`api/fixture-graph.ts`) and its header carry the "this is product code"
   statement instead.
6. **Gap 6 rewrote 37 test import lines rather than leaving a re-export
   bridge in `fixtures/graph.ts`.** A bridge would have been one file, but
   `fixtures -> api` is not an allowed edge either, and two names for one
   dataset is the drift the rule is about.
7. **`lib/backlinks.ts` exports a pure function; `lib/use-query-node-rows.ts`
   exports a hook.** Asymmetric on purpose: backlinks resolve synchronously
   from the index, so the component keeps its memo; query rows have a
   subscription lifecycle, which is the thing gap 8 says a component must not
   own.
8. **`toast` inverted instead of moving.** Argued from the matrix, not from
   taste — see gap 9 above. It is the one place a gap's stated `closes` was not
   followed, and the deviation is recorded in the commit message, in this
   report, and reachable from the gap.
9. **`toast()` with no sink logs instead of returning silently.** A registered
   sink is a hole if nothing registers; `lib/log` makes that hole visible.
10. **Gap 10 was measured and reverted, not sanctioned.** No `UI_ALLOWS` row,
    no fresh markers. Its `current` now names the four breaches by file:line
    and points at the gap that owns them.
